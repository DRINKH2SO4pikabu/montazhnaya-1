# V9: подтвердить кадр после seek без кратковременного воспроизведения

## Симптом

При экспорте на Windows окно экспорта сообщало: целевое время 0.125 с, `currentTime=0.125`, `seeked=true`, но `requestVideoFrameCallback` после запуска воспроизведения наблюдал кадр на 0.167 с. Это было ошибочно интерпретировано как перескок при seek.

## Исправление

Убрано кратковременное `play()` для подтверждения кадра. Теперь после `seeked` функция ожидает наличие декодированного изображения (`readyState >= HAVE_CURRENT_DATA`, корректные размеры видео, `seeking=false`), даёт браузеру возможность отрисовки и повторно проверяет, что `currentTime` остаётся у запрошенного времени в пределах допуска. Это избегает ложного отказа, когда `requestVideoFrameCallback` выдаёт следующий кадр после возобновления воспроизведения.

## Ограничение

Модульные тесты проверяют логику ожидания и защищают от регрессии, но реальный CFR-экспорт в Electron на Windows необходимо подтвердить интеграционным тестом с оригинальным видео. Число кадров и равномерные PTS сами по себе не доказывают уникальность изображения каждого кадра.
