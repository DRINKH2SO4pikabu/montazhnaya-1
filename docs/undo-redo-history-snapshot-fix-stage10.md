# Stage 10 — защита снимков Undo/Redo от общих вложенных объектов

## Проблема

В `History.snapshot()` клипы копировались через `Object.assign({}, clip)`. Это была только поверхностная копия: вложенные объекты `transIn` и `transOut` оставались общими для текущего состояния проекта и старых снимков истории.

Некоторые операции редактирования изменяют длительность перехода непосредственно (`clip.transIn.duration = ...`, `clip.transOut.duration = ...`). В результате менялся не только текущий клип, но и уже записанные снимки истории. На исходной Stage 9 это воспроизводилось: после изменения входящего перехода с 2.0 до 1.25 секунды команда Undo возвращала 1.25 вместо исходных 2.0 секунд.

## Исправление

В модуле `History` добавлен `cloneClip(clip)`. Он сохраняет поверхностное копирование скалярных свойств клипа, но отдельно копирует вложенные объекты `transIn` и `transOut`. Метод используется:

- при создании снимка истории;
- при восстановлении снимка в активную модель проекта.

Вторая часть важна: после Undo/Redo активный клип также не должен ссылаться на объект, принадлежащий сохранённому снимку. Это защищает ветку Redo от последующих изменений в активной модели.

Массив `project.media` по-прежнему копируется поверхностно намеренно: записи медиа содержат ссылки на `File`, `Blob` и object URL, которые нельзя бездумно клонировать через JSON или `structuredClone` в текущей модели редактора.

## Регрессионные тесты

Добавлен `tests/history-snapshot.test.cjs`:

1. Undo восстанавливает исходную длительность `transIn` и `transOut` после изменения вложенных свойств на месте.
2. Redo возвращает новые значения переходов.
3. Изменение восстановленного активного клипа не повреждает сохранённый снимок Redo.
4. Отсутствующие переходы остаются `null`.

## Ручная проверка в Windows

1. Откройте копию проекта, в котором есть видеоклип с входящим переходом.
2. Запомните длительность перехода (например, 2.00 с).
3. Измените её в панели свойств на 1.25 с и примените изменение.
4. Нажмите `Ctrl+Z`: ожидается исходное значение 2.00 с.
5. Нажмите `Ctrl+Y`: ожидается новое значение 1.25 с.
6. Повторите для исходящего перехода.
7. Убедитесь, что обычный клип без переходов продолжает отменяться и повторяться без ошибок.
