# Проверка видеоэкспорта «Монтажной»

## Что проверяется

Экспорт MP4 теперь должен подтвердить не только количество кадров и средний FPS, но и временные метки каждого кадра. Проверка анализирует весь поток PTS, не только первые 300 кадров, и отклоняет результат при отсутствующих временных метках, повторяющихся/непоследовательных PTS, слишком больших разрывах или интервалах, не соответствующих ожидаемой CFR-сетке.

В `electron/media-timing.cjs` находится общий анализатор временных меток. `electron/main.cjs` вызывает его при проверке исходного WebM и готового MP4. Режим «MP4 (локальный FFmpeg)» получает пронумерованные PNG-кадры через preload IPC, кодирует H.264 и при необходимости добавляет AAC; итог проверяется в главном процессе. WebM и встроенный MP4 остаются realtime-режимами MediaRecorder, для них строгая CFR-сетка не гарантируется.

## Автоматические модульные тесты

Из каталога проекта запустить в Windows PowerShell или CMD:

```powershell
npm.cmd test
```

Тесты намеренно включают временной разрыв после 300-го кадра, чтобы поймать регрессию, которую старый ограниченный просмотр первых 300 PTS пропускал.

## Проверка готового MP4

Для команд ниже нужны `ffmpeg` и `ffprobe` в `PATH`. Эталонные тестовые MP4 не хранятся в Git: создайте их из встроенных синтетических фильтров FFmpeg командой `node tools/generate-synthetic-fixtures.cjs`. Скрипт использует `testsrc2` и `sine`, не загружает пользовательские или сторонние медиа, а создаваемые файлы исключены из Git через `.gitignore`. Проверяющий скрипт находится в `tests/inspect-export.cjs` и анализирует весь поток PTS, кодек, размер кадра, число кадров, частоту, длительность, аудиопоток и возможность полного декодирования.

### 1. Эталонный ролик 30 FPS со звуковыми маркерами

Импортировать в редактор `tests/fixtures/synthetic-30fps-audiomarkers.mp4`, поместить начало клипа на 0 секунд и экспортировать 7 секунд в MP4 при 30 FPS. Затем проверить экспортированный файл:

```powershell
node tests/inspect-export.cjs "C:\путь\к\экспорту.mp4" --fps 30 --frames 210 --duration 7 --audio-markers --require-motion
```

Ожидается 210 кадров, 30 FPS, длительность около 7 секунд, H.264/yuv420p, AAC с началом около 0 секунд, отсутствие ошибок декодирования и равномерные PTS. Скрипт дополнительно ищет три звуковых импульса около 0.20, 3.50 и 6.80 секунды (допуск ±0.10 секунды) и проверяет, что соседние кадры не идентичны побайтно.

### 2. Экспорт 24 FPS

Экспортировать семисекундный тестовый ролик при 24 FPS и проверить результат:

```powershell
node tests/inspect-export.cjs "C:\путь\к\экспорту-24fps.mp4" --fps 24 --frames 168 --duration 7 --audio-markers
```

Ожидается 168 кадров. Параметр `--require-motion` здесь намеренно не используется: при преобразовании частоты кадров совпадающие соседние кадры могут быть нормальным следствием повторения исходного кадра.

### 3. Источник 25 FPS, экспорт 30 FPS

Импортировать `tests/fixtures/synthetic-25fps-audiomarkers.mp4` и экспортировать 7 секунд при 30 FPS:

```powershell
node tests/inspect-export.cjs "C:\путь\к\экспорту-25-to-30.mp4" --fps 30 --frames 210 --duration 7 --audio-markers
```

Ожидается 210 кадров с шагом PTS около 1/30 секунды и звуковыми маркерами в ожидаемых позициях.

## Как читать результат

Каждая строка `PASS` означает, что конкретная проверка выполнена; `FAIL` означает, что скрипт завершится с кодом 1. Финальная строка показывает общий итог. Для проверки звука укажите `--audio-markers`, для экспорта без звука — `--no-audio`. Используйте `node tests/inspect-export.cjs --help` для справки.

## Ограничение текущей автоматической проверки

Модульные тесты и тесты FFmpeg проверяют алгоритм анализа PTS, подготовку PNG-последовательности и поведение кодирования на эталонных файлах. Они **не подменяют** ручной запуск приложения на Windows. Для локального MP4 дополнительно нужно подтвердить, что отрендеренные изображения соответствуют ожидаемым сценам; для WebM и встроенного MP4 — что realtime-захват не теряет кадры при реальной нагрузке. Для окончательной приёмки экспортируйте тестовый ролик через интерфейс «Монтажной», затем запустите `tests/inspect-export.cjs` для полученного файла.

## Безопасный откат

Перед заменой файлов сделайте резервную копию проекта. Установщик аудита 3.6.4 сохраняет заменяемые файлы в отдельную папку внутри `backups/`; для отката восстановите оттуда прежние файлы. Временные синтетические тестовые ролики можно удалить и повторно создать командой `node tools/generate-synthetic-fixtures.cjs`.
