# QA — «Монтажная» beta 3.6.19

## Изменённый сценарий

Один будущий source frame prefetch выполняется параллельно с PNG-сериализацией и IPC-записью текущего кадра. Следующий PNG не передаётся, пока main process не подтвердил запись предыдущего.

## Автоматические проверки

- 173/173 теста — PASS, 0 ошибок, 0 пропусков.
- Проверено сохранение строго возрастающих индексов кадров.
- Проверен статический контракт однокадрового prefetch и одновременного ожидания записи/чтения.
- Проверены ошибки, таймкоды и потоки существующих тестов MP4/WebM.
- Реальные FFmpeg-интеграционные тесты кодирования и проверки BT.709 пройдены.
- Синтаксис main/preload/frame-sequence и встроенного JS renderer проверен.

## Ожидаемое измерение на Windows

Повторить тот же проект, который использовался для beta 3.6.18:
- 3840×2160;
- 60 FPS;
- MP4 H.264 + AAC;
- средний битрейт 20 Мбит/с;
- тот же исходник и тот же отрезок 6,05 с.

Сравнить итоговое время, чтение/декодирование, PNG-сериализацию, `sourcePrefetchOverlapMs`, передачу FFmpeg и финализацию. Суммарные времена отдельных задач могут перекрываться и не должны складываться как последовательная длительность.

## Ограничения

Автоматические тесты не измеряют ускорение на конкретном CPU пользователя. Патч вводит только ограниченное перекрытие одного следующего source frame; он не меняет сам PNG-энкодер Canvas и не устраняет стоимость 4K-сериализации. Источник 24 FPS при выходе 60 FPS по-прежнему преобразуется в CFR 60 FPS с повторением некоторых исходных моментов; интерполяция движения не добавлена.
