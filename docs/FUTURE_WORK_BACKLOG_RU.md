# «Монтажная» — список будущей работы после аудита beta 3.6.4

Документ для переноса задач в следующие этапы разработки. Это выявленные ограничения и пункты проверки; они не все являются неисправностями.

## P0 — надёжность MP4-экспорта

- [x] **Убрать лимит 128 МиБ на исходное видео (beta 3.6.6).** Реализовано потоковое обращение к источнику без передачи целого видео через IPC.
  Для обычных файлов на диске FFmpeg получает путь через `webUtils.getPathForFile`; файлы из памяти/переносимых проектов передаются в главный процесс последовательными блоками до 8 МиБ с проверкой размера, порядка и владельца, после чего обрабатываются с диска. Точное декодирование выбранных кадров и анализ WebM больше не требуют `File.arrayBuffer()` целиком. Встроенный звук видео извлекается FFmpeg в WAV с выравниванием смещения аудио относительно видео.
  Проверено на реальном MP4 H.264/AAC размером 137 653 962 байта (около 131,3 МиБ): ffprobe распознал оба потока, FFmpeg извлёк кадры и PCM WAV. Автотесты: 73/73.
  **Остаточные лимиты:** 2 ГиБ на временный кэш PNG-кадров; 512 МиБ на WAV временного извлечения; 256 МиБ на декодированный AudioBuffer Chromium; 512 МиБ на портативный ZIP-пакет проекта. Последний пока упаковывает медиа целыми буферами. Эти ограничения не возвращают лимит 128 МиБ на исходное видео, но требуют отдельного потокового аудиомикшера, оценки диска и потоковой упаковки проекта.
- [x] **Отменять FFmpeg на этапе финального кодирования (реализовано в beta 3.6.5; ручная приёмка Windows ожидает проверки).** Отдельный процесс через `spawn`, прогресс через IPC, graceful quit командой `q`, отложенный принудительный terminate; временная сессия остаётся заблокированной до фактического закрытия процесса, затем очищается.
- [x] **Показывать проверку FFmpeg/ffprobe в интерфейсе (реализовано в beta 3.6.7; ручная приёмка Windows ожидает проверки).** Команда «Справка → Диагностика FFmpeg и ffprobe…» показывает наличие, путь и версию обоих инструментов, проверяет libx264, AAC, MP4 muxer и PNG decoder, выполняет пробное MP4-кодирование без звука и с AAC и проверяет результат через ffprobe. Поддерживаются PATH, FFMPEG_PATH и FFPROBE_PATH. Временные тестовые файлы удаляются автоматически. Для экспорта используется тот же резолвер исполняемых файлов, что и в диагностике. Автотесты нового модуля и интеграционные тесты реального FFmpeg/ffprobe пройдены.
- [x] **Проверять место на диске перед экспортом (beta 3.6.8, уточнено в 3.6.9; ручная приёмка Windows ожидает проверки).** Используется `fs.promises.statfs`; до экспорта оцениваются WAV, временный MP4, конечная копия и резерв, отдельно проверяются временный и целевой тома. При дефиците по базовой оценке экспорт блокируется; при пограничном запасе или невозможности проверки показывается предупреждение. Во время подготовки и финализации место проверяется повторно. В beta 3.6.9 финальные PNG больше не сохраняются последовательностью на диск — они передаются в FFmpeg через `image2pipe`, поэтому их постоянный дисковый объём в streaming mode равен нулю. **Остаточные ограничения после beta 3.6.10:** отдельный дисковый LRU-кэш исходных PNG ограничен 512 МиБ, а декодированные изображения Renderer — 256 МиБ; старые кадры вытесняются и при повторном использовании декодируются заново. WAV ограничен 512 МиБ, а исходный OfflineAudioContext/AudioBuffer не стал потоковым. Автотесты beta 3.6.9: 102/102. Ручная проверка предупреждений и исчерпания диска на Windows ещё требуется.
- [x] **Убрать хранение финальной PNG-последовательности на диске (beta 3.6.9).** Главный процесс запускает FFmpeg с `image2pipe`, Renderer передаёт один PNG-кадр через узкий IPC API и ждёт завершения бинарной записи до отправки следующего кадра; это создаёт backpressure. WAV заранее помещается в сессию и подключается вторым входом. FFmpeg задаёт CFR, кодирует H.264 и AAC, сообщает прогресс через IPC. Отмена бинарного потока не посылает текст `q` в stdin; процесс закрывается до очистки временной сессии. Реальный FFmpeg 7.1.5 проверен на H.264/AAC, CFR 25 FPS, отмене и 3 кадрах 4K/24 FPS. Это интеграционное подтверждение конвейера, не приёмка долгого 4K60.
- [x] **Заменить накопительный кэш исходных PNG-кадров оконным LRU (beta 3.6.10).** Прежний лимит 2 ГиБ на совокупность исходных PNG больше не ограничивает длительность/число кадров проекта. Главный процесс регистрирует план кадров, но не декодирует их заранее. При запросе кадра FFmpeg декодирует небольшое окно вокруг нужного source-frame index; для удалённых окон используется входной seek `-ss` с `-copyts`, а фильтр выравнивает timestamps относительно исходного `start_time` и начального CFR-индекса окна. Это предотвращает повторное декодирование всего файла с нулевого кадра при каждом обращении. Окна ограничены количеством кадров и временным span; разреженный план не заставляет декодировать большие промежутки между повторно использованными клипами.
  На диске действует общий LRU-бюджет 512 МиБ на сессию: старейшие PNG удаляются, а при повторном обращении к вытесненному кадру он декодируется снова. Для планирования окна используется консервативная оценка до raw RGBA + небольшой overhead, чтобы шумные изображения не превышали резерв диска. В Renderer декодированные RGBA-поверхности учитываются по байтам и ограничены 256 МиБ; одиночный кадр крупнее этого бюджета не сохраняется в постоянном кэше после текущей композиции. Временные исходники из staging сохраняются на время экспортной сессии и удаляются при завершении/отмене.
  Побитово сравнивались выбранные кадры из полного декодирования и ленивых окон при 24/25/30/60 FPS; отдельно проверен источник с ненулевым `start_time`. Все 113 автоматических тестов beta 3.6.10 прошли, в том числе реальные FFmpeg/ffprobe интеграционные тесты. **Остаточные ограничения:** диск-кэш всё ещё ограничен 512 МиБ, Renderer-кэш — 256 МиБ; при сложном нелинейном повторном доступе вытесненные кадры будут декодироваться заново. Это ограничивает одновременно хранимые данные, а не общую длительность исходного видео. Ручная проверка на Windows/Electron и длинных проектах с несколькими видеослоями остаётся обязательной.

- [ ] **Протестировать длительные и тяжёлые экспорты.** Сценарии 1080p/4K, 24/25/30/60 FPS, длинные ролики, несколько видеослоёв, с аудио и без аудио.

### Результат beta 3.6.10 — оконный кэш исходных кадров

- Убран накопительный лимит 2 ГиБ для PNG-кадров, декодированных из исходного видео в streaming MP4: кадры извлекаются небольшими окнами по требованию.
- Входной seek сохраняет `start_time` исходного видеопотока и CFR-фазу; выбранные кадры побитово совпадают с full-decode reference на 24/25/30/60 FPS и при ненулевом начале потока.
- Дисковый LRU-кэш ограничен 512 МиБ на экспортную сессию; Renderer-кэш декодированных RGBA-изображений — 256 МиБ.
- Размер окна динамически уменьшается по консервативной оценке raw RGBA и по фактическому размеру PNG; для sparse-планов введён предел временного span.
- Полный набор: 113/113 тестов. Интеграционные тесты запускают локальный FFmpeg; реальная Windows/Electron GUI-проверка и длительный многослойный экспорт выполняются отдельно.


### Результат beta 3.6.11 — CFR WebM и единый локальный экспорт

- Локальный MP4 H.264/AAC, WebM VP8/Opus и WebM VP9/Opus используют один покадровый потоковый FFmpeg pipeline с бинарным stdin и backpressure.
- Для Electron скрывается дублирующий realtime MP4, если локальный MP4 кодек прошёл capability check. Browser MediaRecorder fallback явно помечается как realtime, FPS не гарантирован.
- WebM verifier учитывает 1 мс временную сетку контейнера и Opus pre-skip; аудио проверяется по пакетам, когда stream duration отсутствует.
- Диагностика FFmpeg/ffprobe дополнена VP8/VP9/Opus и реальными тестовыми кодированиями WebM.
- Справка экспорта, обучающий тур и предупреждения длинных проектов исправлены: локальные MP4/WebM описаны как offline FFmpeg CFR; realtime и отсутствие гарантии FPS указаны только для браузерного fallback.
- Интеграционные FFmpeg tests: VP8/Opus 25 FPS и VP9/Opus 60 FPS; полный набор: 118/118.
- Требуется ручной Windows GUI/export regression на реальном проекте и визуальная сверка 20 переходов.

## P1 — звук, кадры и визуальное качество

- [x] **Стабилизировать WebM и встроенный MP4 (beta 3.6.11; ручная приёмка Windows ожидает проверки).** В Electron локальные MP4 H.264/AAC и WebM VP8/Opus либо VP9/Opus переведены на единый покадровый FFmpeg-конвейер через PNG `image2pipe`, offline WAV и целочисленный CFR-план; MediaRecorder оставлен только как явно помеченный realtime fallback, когда локальный кодек недоступен или редактор открыт вне Electron. Для WebM ffprobe проверяет контейнер, выбранный видеокодек, `yuv420p`, точное число кадров, `avg_frame_rate`, все PTS и временной диапазон Opus. Допуск PTS учитывает 1-мс time_base WebM; Opus pre-skip около −7 мс не считается ошибкой, а покрытие проверяется по временным меткам пакетов, если stream duration отсутствует. Встроенная диагностика теперь пробно кодирует и проверяет MP4 без звука/с AAC, WebM VP8+Opus и WebM VP9+Opus. Реальные FFmpeg-тесты проверили VP8 при 25 FPS и VP9 при 60 FPS. Полный набор beta 3.6.11: 119/119. **Остаточная ручная проверка:** длинный многослойный проект и воспроизведение VP8/VP9 в целевых Windows-плеерах; полное сравнение preview/export для 20 переходов остаётся отдельной задачей.
- [x] **Расширить диагностику аудиокодеков (beta 3.6.12; ручная приёмка Windows ожидает проверки).** ffprobe анализирует аудиопотоки до Chromium, выбирает `default` или первый доступный поток, фиксирует кодек/профиль/частоту/каналы. Кодеки за пределами безопасного набора Chromium, многоканальный звук и частоты выше 48 кГц нормализуются в PCM 16-bit WAV, 48 кГц, стерео для предпрослушивания и OfflineAudioContext. Проверены MP3, AAC, OGG/Vorbis, FLAC, WAV PCM24, AC-3, E-AC-3, WMA2 и DTS при наличии соответствующих энкодеров сборки FFmpeg. 5.1 корректно сводится в стерео. Для длительного или слишком большого preview предусмотрено явное предупреждение; WAV/AudioBuffer лимиты не скрываются.
- [x] **Проверить синхронизацию звука (beta 3.6.12; длинный Windows GUI-проект ещё требует ручной приёмки).** Встроенный звук видео выбирается через ffprobe и выравнивается относительно начала видеопотока: положительное смещение дополняется тишиной, отрицательное обрезает ранние сэмплы. Один и тот же `buildPcmWavNormalizeArgs` используется для preview-normalization и извлечения встроенного звука в экспорт, а экспорт возвращает фактическую длительность WAV с учётом offset. Проверено на реальных сэмплах для +200 мс и −125 мс, в контейнере с двумя аудиопотоками выбран `default`. Offline mixer сводит несколько аудиодорожек, встроенный звук видео, отделённый звук, громкость клипа/дорожки и fade-in/out. Видеоклип, у которого звук отделён, не добавляется повторно в микс. Audio crossfade реализован equal-power sin/cos, применяется в realtime preview и OfflineAudioContext, хранится в проекте и удаляется через контекстное меню. Автоматические проверки: 136/136. **Остаточные лимиты:** WAV до 512 МиБ, decoded AudioBuffer до 256 МиБ, preview WAV до 96 МиБ; длинные музыкальные проекты потребуют потокового аудиомикшера. Реальная проверка длинного многодорожечного проекта на Windows/Electron и сравнение финального файла с предпросмотром остаются обязательными.
- [ ] **Сверить предпросмотр с конечным файлом (частично подготовлено в beta 3.6.13–3.6.14).** Общий Canvas-композитор используется preview и локальным экспортом; исправлено масштабирование титров для разрешений вывода и наследование титрами transition zoom/spin; preview/export Canvas явно используют sRGB и одинаковое сглаживание. Автотесты подтверждают 20 transition render-state и структурный паритет, но не доказывают pixel-perfect совпадение Chromium decode и FFmpeg decode. В beta 3.6.14 дополнительно: paused seek tolerance сделан FPS-зависимым для video/audio preview; PNG sRGB/full-range явно преобразуется в limited-range BT.709 YUV420P; MP4/WebM маркируются `color_range=tv`, `colorspace=bt709`; реальные FFmpeg/ffprobe тесты проверяют эти metadata и RGB sample error. Полный набор beta 3.6.14: 149/149. Это укрепляет timing и SDR color pipeline, но не доказывает pixel-perfect совпадение Chromium и FFmpeg. Остаётся ручная Windows/Electron проверка контрольных кадров MP4/WebM, SSIM/PSNR на сложной сцене, HDR/ICC/Display-P3 и всех эффектов.
- [ ] **Проверить все 20 переходов визуально.** Каталог и код отрисовки содержат обработку каждого режима; требуется реальная проверка направления, длительности, стыка и результата MP4/WebM.

### Результат beta 3.6.12 — совместимость аудио и временная синхронизация

- ffprobe анализирует входные аудиопотоки; по умолчанию выбирается поток с `disposition.default=1`, иначе первый аудиопоток.
- Небраузерные/неподдерживаемые кодеки, многоканальные источники и частоты выше 48 кГц нормализуются в 48 кГц stereo PCM16 WAV для предпрослушивания; медиатека отображает профиль источника и состояние fallback.
- Встроенный звук видео выравнивается по началу видеопотока; offset-путь общий для предпрослушивания и экспорта. Проверены реальные WAV-сэмплы для положительного и отрицательного смещения, а также выбор default audio stream из двух дорожек.
- Аудио crossfade использует equal-power sin/cos, семплируется как в realtime preview, так и в offline mix, сохраняется в проекте.
- Проверены MP3, AAC, OGG/Vorbis, FLAC, WAV PCM24, AC-3, E-AC-3, WMA2, DTS (по наличию кодеков FFmpeg) и downmix 5.1 → stereo.
- Полный набор beta 3.6.12: 136/136.
- Остаточные ограничения: WAV 512 МиБ, preview WAV 96 МиБ, суммарная AudioBuffer память 256 МиБ. Нужен потоковый аудиомикшер для длинных треков; ручной end-to-end тест многодорожечного проекта в Windows/Electron ещё не выполнен.

### Результат beta 3.6.13 — основа паритета preview/export

- Предпросмотр и локальный покадровый экспорт используют `renderSequenceAtTime()` как общий Canvas-композитор.
- `getCanvasDesignScale()` масштабирует авторский размер титров из разрешения проекта в разрешение выходного Canvas; вместе с ним масштабируются межстрочный интервал и отступы.
- Титры наследуют общий сдвиг и переходные `transitionScale`/`transitionRotation`, а не остаются в прежнем масштабе и угле при zoom/spin.
- Оба Canvas-контекста явно запрашивают sRGB и используют одинаковые параметры image smoothing.
- Добавлено 7 parity-тестов; полный набор beta 3.6.13: 143/143.
- **Не закрыто:** ручная визуальная сверка 20 переходов; прямое сравнение Chromium HTMLVideoElement и FFmpeg декодированных кадров; HDR/ICC/full-vs-limited range; произвольные маски пользователя отсутствуют (доступны только маски переходов).
