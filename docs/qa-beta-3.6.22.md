# QA beta 3.6.22 — NVDEC with source-specific fallback

## Изменения

- В `electron/video-decode.cjs` добавлена политика выбора NVDEC и безопасное сопоставление pixel format.
- Для `yuv420p`, `yuvj420p`, `nv12` используется `nv12`; для `yuv420p10le`, `p010le` — `p010le`. Остальные форматы пока используют программный декодер.
- Перед первым оконным чтением исходного видео выполняется реальная однокадровая проба `-hwaccel cuda -hwaccel_output_format cuda` с `hwdownload`.
- При неудаче проба запоминает software mode для текущего источника. Если реальное последующее окно NVDEC не запускается, оно удаляется и пересоздаётся программным декодером; экспорт продолжается.
- Обычный software decode остаётся режимом по умолчанию для форматов вне allowlist и для FFmpeg без работоспособного CUDA.
- Диагностика FFmpeg показывает CUDA в списке `-hwaccels`, но не выдаёт это за успешную проверку физического устройства.

## Тесты

- Полный набор `npm test`: **198/198 PASS**, 0 failed, 0 skipped.
- `node --check` для всех CommonJS-файлов в `electron/` и `tests/`: PASS.
- Ручная проверка на приложенном 4K60 H.264 исходнике (`yuv420p`): программное однокадровое декодирование FFmpeg завершилось с кодом 0; CUDA-проба в текущем Linux-контейнере завершилась ожидаемой ошибкой `Cannot load libcuda.so.1`, так как в контейнере нет NVIDIA runtime/GPU.
- Unit tests подтверждают pixel format allowlist, успешный и неуспешный runtime probe, аргументы NVDEC probe, точность CFR/seek фильтра и отсутствие изменений в software default path.
- Интеграционные source-frame tests сравнивают хэши выбранных кадров с полной CFR-последовательностью на 24/25/30/60 FPS. Эти тесты исполняются на программном декодере текущей среды.

## Ограничения проверки

- Физический NVDEC не проверен: текущая среда не имеет доступного NVIDIA GPU.
- На Windows пользователя текущая сборка FFmpeg требует NVENC API 13.1, а драйвер 582.66 предоставляет API 13.0. Следовательно, текущая сборка не годится для доказательства NVDEC на этом драйвере: сначала нужен FFmpeg, собранный с `nv-codec-headers` 13.0.x.
- Отдельный совместимый FFmpeg binary в этой версии не собран/не приложен.
- Нельзя обещать ускорение экспорта до сравнения времени и визуальной идентичности на той же контрольной выборке. Данные кадры после NVDEC всё равно передаются в системную память для композиции Canvas.

## Ручная проверка на Windows после установки совместимого FFmpeg

1. Указать путь к совместимой сборке через `FFMPEG_PATH` либо добавить её `bin` в `PATH`; `ffprobe.exe` должен идти из той же папки через `FFPROBE_PATH`/`PATH`.
2. Полностью перезапустить редактор.
3. Экспортировать тот же короткий 4K60 исходник.
4. Найти ASCII-маркер `[NVDEC_PROBE_PASS]` и `decoder: cuda`. При отказе появится `[NVDEC_SOFTWARE_FALLBACK]`; если проба прошла, но упало одно из последующих окон, появится `[NVDEC_WINDOW_FALLBACK]`.
5. Убедиться, что оконный кэш декодирует точное число кадров, экспорт MP4 проверяется как H.264/AAC с исходным target FPS, а полное декодирование завершается без ошибок.
6. Повторить экспорт с отключённым/недоступным CUDA; программа должна продолжить работу с software decode.

## Воспроизводимая диагностика FFmpeg на Windows

В `tools/Test-MontazhnayaGpu.ps1` добавлен отдельный диагностический скрипт. Он принимает явные пути к `ffmpeg.exe` и тестовому видео, проверяет `ffprobe.exe` из той же папки, записывает версию/список hwaccels/кодеков, сведения `nvidia-smi`, а также запускает три реальные проверки: однокадровое программное декодирование, NVENC H.264-кодирование и NVDEC/CUDA-декодирование исходного файла с выгрузкой кадров в системную память.

Пример запуска из корня распакованного проекта в PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\Test-MontazhnayaGpu.ps1 `
  -FfmpegPath (Join-Path $env:LOCALAPPDATA 'Montazhnaya\ffmpeg-8.0.1-nvenc-api13.0\ffmpeg.exe') `
  -InputVideoPath (Join-Path $env:USERPROFILE 'Downloads\montazhnaya_20261102_1710.mp4')
```

Скрипт сохраняет текстовый отчёт в `gpu-diagnostics`. Наличие `cuda` в `-hwaccels` само по себе не считается успешным NVDEC: нужен `PASS` реального однокадрового декодирования. Аналогично для NVENC требуется успешный runtime encode.


## Последующая проверка на реальном оборудовании (после сборки beta 3.6.22)

В отдельной Windows-сборке Gyan FFmpeg 8.0.1 пользователь получил `NVENC SMOKE TEST: PASS` с GTX 1050 и драйвером, предоставляющим NVENC API 13.0. Запуск beta 3.6.22 показал `NVDEC_PROBE_PASS`; последующие окна исходного видео декодировались через CUDA без fallback. Финальный экспорт выбрал `h264_nvenc` и полностью прошёл проверку MP4. Источником этого конкретного NVENC-экспорта был уже перекодированный файл 1280×720, поэтому время 42,4 с не является сопоставимым benchmark с предыдущим экспортом оригинального 4K60-файла. Подробный протокол честного сравнения: `docs/benchmark-protocol-3.6.23.md`.
