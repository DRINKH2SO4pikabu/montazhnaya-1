# Исправление гонки `currentTime` / `seeked` при покадровом экспорте

Дата: 2026-10-17

## Наблюдаемая проблема

При экспорте Electron показывал, что `currentTime` уже равен целевой временной метке, `readyState=4` и `seeking=false`, однако `requestVideoFrameCallback` продолжал сообщать старый кадр (`mediaTime=0.000`). Экспорт останавливался по тайм-ауту. Ранее созданные MP4 также могли содержать повторы/пропуски изображений, хотя число кадров и PTS выглядели корректно.

## Причина в коде

В `src/renderer/index.html`, внутри `seekVideoElement()`, `waitForSeekedTo()` присваивал `el.currentTime = seekTarget`, затем немедленно проверял `currentTime` и `seeking`. В Chromium значение `currentTime` может обновиться до завершения асинхронного seek/decode. Эта проверка ошибочно принимала обновление свойства за окончание перемотки и могла разрешать отрисовку старого декодированного изображения.

## Что изменено

- Быстрый путь «элемент уже на нужном времени» проверяется по значению `currentTime` **до** присваивания.
- Если целевая отметка отличается, функция ждёт настоящее событие `seeked`; немедленное обновление `currentTime` больше не завершает ожидание.
- `requestVideoFrameCallback` по-прежнему используется как более сильное подтверждение кадра.
- Если после реального события `seeked` Chromium не выдаёт целевой compositor callback в течение короткого окна, код может продолжить только при отсутствии ошибки медиадекодера, `seeking=false`, наличии декодированных видеоданных и соответствии `currentTime` целевой отметке. Это исключает 7-секундный тупик, вызванный только отсутствием callback; это не подменяет проверку фактического результата экспорта.
- Добавлен регрессионный тест, моделирующий ситуацию, когда `currentTime` обновляется немедленно, а `seeked` приходит позже.

## Проверки, выполненные в этой среде

- `npm test`: 7/7 тестов пройдены.
- `node --check electron/main.cjs`: пройдено.
- `node --check electron/preload.cjs`: пройдено.
- Извлечённый встроенный JavaScript из `src/renderer/index.html`: `node --check` пройден.
- Тестирован именно порядок ожидания в симуляции DOM-событий. Полноценный экспорт внутри Electron на Windows в этой среде не запускался.

## Ручная проверка в Windows

1. Открыть исходный `video (3).mp4` в редакторе.
2. Выставить FPS последовательности и экспорта одинаково — 24 FPS — для чистого теста.
3. Экспортировать 10 секунд в MP4.
4. Если экспорт завершился, сравнить результат с оригиналом по изображениям всех кадров, а не только по числу кадров/PTS.
5. Если экспорт снова остановился, сохранить полный текст ошибки и файл нового экспорта, если он был создан.

## Ограничение

Результат нельзя считать окончательно подтверждённым до проверки реального MP4, экспортированного в Electron на Windows. Ровные PTS и ожидаемое число кадров сами по себе не доказывают, что все исходные изображения сохранены.
