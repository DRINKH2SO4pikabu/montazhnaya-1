# «Монтажная» beta 3.6.6 — обработка больших исходных видео

## Цель релиза

Убрать прежнее ограничение 128 МиБ на исходный видеоматериал в точном MP4-конвейере и при анализе WebM, перестав передавать целый исходный видеофайл из Renderer в Main одним `ArrayBuffer`.

## Что изменено

- Для обычных файлов с диска Preload получает системный путь через `webUtils.getPathForFile(file)` и передаёт в Main только ссылку на источник. Исходные байты не копируются через IPC.
- Для файлов, созданных в памяти (например, восстановленных из переносимого проекта), добавлена временная дисковая передача порциями по 8 МиБ. Каждый IPC-вызов ожидается перед отправкой следующего фрагмента; Main проверяет порядок, владельца, размер и итоговую длину.
- FFmpeg напрямую читает дисковый исходник при точном извлечении выбранных кадров. На диск попадают только PNG-кадры, действительно необходимые текущему экспортному проекту.
- Анализ длительности WebM также использует путь/временный дисковый источник и ffprobe, без загрузки всего видео в Renderer.
- Встроенная аудиодорожка видеоматериала извлекается FFmpeg во временный WAV 48 кГц, стерео, PCM 16-bit. Сдвиг аудио относительно видеопотока корректируется до декодирования.
- Временные копии источников удаляются после завершения FFmpeg/ffprobe, при закрытии окна — все временные загрузки владельца очищаются.
- Добавлен модуль `electron/staged-file.cjs` и тесты передачи порциями, проверки целостности, изоляции окна и размера больше 128 МиБ.

## Важные ограничения — не считать «безлимитным» весь редактор

- Убран лимит **размера самого исходного видео 128 МиБ** для точного MP4-декодирования и анализа WebM. Размер видео ограничивается файловой системой, временем работы FFmpeg и доступным диском, а не прежним лимитом IPC.
- Временный кэш выбранных PNG-кадров по-прежнему ограничен 2 ГиБ на сессию экспорта. Это ограничение кэша кадров, а не размера исходного файла.
- Встроенный звук видео для текущего OfflineAudioContext всё ещё декодируется в память Chromium. Сохраняется ограничение 256 МиБ на суммарный декодированный AudioBuffer; WAV временно ограничен 512 МиБ. Длинное видео без звука или с коротким аудиофрагментом может обрабатываться, но очень длинный встроенный звук потребует отдельного потокового аудиомикшера (следующая задача P1/P0 по ресурсам).
- Портативный архив проекта имеет собственный лимит 512 МиБ и пока сериализует вложенные медиа целиком. Это отдельная задача переносимости/потоковой упаковки, не равная декодированию видео с диска.
- Обычные отдельные аудиофайлы пока декодируются существующим Web Audio путём. Этот релиз убирает целиком-буферную передачу **видеофайлов**, но не вводит потоковый аудиомикшер.

## Изменённые файлы

- `electron/staged-file.cjs` — временное хранилище для файлов, доступных только как Blob/File в памяти.
- `electron/preload.cjs` — использование `webUtils.getPathForFile`, передача дискового пути или чанков по 8 МиБ.
- `electron/main.cjs` — проверка IPC-источника, разрешение локального/временного источника, FFmpeg-декодирование видео и извлечение встроенного аудио.
- `src/renderer/index.html` — удаление прежнего ограничения 128 МиБ, использование нового узкого Preload API; отключение ненужного чтения всего видео ради waveform.
- `tests/staged-file.test.cjs` и `tests/source-frame-extraction.test.cjs` — тесты больших источников и передачи порциями.
- `package.json`, `package-lock.json` — версия beta 3.6.6.
- `docs/FUTURE_WORK_BACKLOG_RU.md` — закрытие первого пункта P0 с фиксацией остаточных лимитов.

## Требования

- Electron 37.x (проект использует `^37.2.6`; необходим `webUtils.getPathForFile`).
- FFmpeg и ffprobe доступны в PATH.
- Достаточно свободного места для временного PNG-кэша и WAV.
