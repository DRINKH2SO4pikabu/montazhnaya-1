# «Монтажная» beta 3.6.22 — отчёт по реальному тесту NVIDIA

Дата пользовательского теста: 2026-11-02.

## Итог

NVDEC на NVIDIA GTX 1050 подтвердил работу на реальном входном файле H.264, 3840×2160, 60 FPS, yuv420p. В журнале есть `NVDEC_PROBE_PASS`, после чего все видимые оконные FFmpeg-команды выполнялись с `-hwaccel cuda -hwaccel_output_format cuda` и `hwdownload,format=nv12`. Маркер `NVDEC_WINDOW_FALLBACK` в представленном фрагменте отсутствует.

Выходной MP4 создан с помощью CPU-кодировщика `libx264`, поскольку исходная сборка FFmpeg требует NVENC API 13.1, а установленный драйвер сообщает API 13.0. AMF не доступен из-за отсутствующей `amfrt64.dll`; QSV не смог создать MFX-сессию.

PCM-аудио после декодирования в обоих файлах имеет одинаковый MD5: `a84e2f5dea0d504f2b90a58ea7455be6`.

PTS видеокадров в обоих файлах идут от 0.000 до 6.000 s с шагом 0.033333 или 0.033334 s (обычная дискретизация 30 FPS).

Метрики SSIM/PSNR — сравнение двух MP4 между собой, не сравнение с lossless-мастером.

## Производительность

По интерфейсным таймингам beta 3.6.22: общее время 151.3 s. Предыдущий пользовательский прогон beta 3.6.21 показывал 143.1 s. Новая попытка на 8.2 s (примерно 5.73%) дольше. Поэтому NVDEC фактчекнут, но ускорение всего проекта пока не подтверждено.

Экспорт beta 3.6.22 использовал `libx264`, поэтому финальное H.264-кодирование выполнялось CPU. NVDEC ускоряет только декодирование исходника; он не ускоряет финальную компрессию. В производственном пути после NVDEC есть hwdownload в NV12, создание PNG-кадров и дальнейшая композиция на CPU, что тоже добавляет затраты.

## Следующий технический шаг

Проверить отдельную сборку Gyan FFmpeg 8.0.1 (Windows x64, SHA-256 из manifest WinGet) с NVENC API 13.0 на драйвере 582.66. Это отдельная тестовая сборка; системный FFmpeg и драйвер не заменяются. После положительного однокадрового / короткого smoke-теста запустить beta 3.6.22 с `FFMPEG_PATH` и `FFPROBE_PATH` на новый бинарник, затем проверить полный экспорт тем же проектом и измерить время.

Официальный заголовочный пакет NVIDIA 13.0.19.1 указывает минимальный Windows-драйвер 570.0; текущий 582.66 выше этого минимума. Это подтверждает подходящий диапазон драйвера, но не заменяет реальный smoke-тест конкретного FFmpeg-бинарника.
