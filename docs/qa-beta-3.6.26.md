# QA report — Montazhnaya beta 3.6.26

Дата подготовки: 2026-11-03

## Изменение

В beta 3.6.25 исходные кадры для точной офлайн-композиции извлекались и передавались в Chromium в полном исходном разрешении, даже если итоговый холст был 1280×720. Для каждого кадра Chromium читал PNG, декодировал полноразмерную RGBA-поверхность, а затем Canvas уменьшал её до разрешения экспорта.

В beta 3.6.26 добавлен export-aware working size:
- рабочий размер зависит от разрешения итогового Canvas;
- используется запас 1,5× и коэффициент 1,25 на переходы;
- максимальный пользовательский `clip.scale` учитывается отдельно для каждого источника;
- апскейл исходного изображения запрещён;
- для 1080p/4K или клипов с большим масштабом сохраняется исходное разрешение, когда запаса рабочей поверхности недостаточно;
- FFmpeg уменьшает только выбранные кадры целевой CFR-сетки, фильтром Lanczos;
- аппаратное NVDEC по-прежнему применяется к исходному H.264, когда probe успешно пройден; масштабирование выполняется после `hwdownload`;
- оригинальные файлы пользователя не изменяются.

Пример для исходника 3840×2160 и экспорта 1280×720 при `clip.scale=1`:
- рабочий PNG: 2400×1350;
- исходник: 3840×2160;
- `renderScale`: приблизительно 0,625.

## Защита и ограничения

- Валидация исходных и целевых размеров: 2–16384 px.
- `maxClipScale` принимается только в диапазоне 0,1–5.
- Размеры остаются чётными для совместимости с 4:2:0.
- Реальная проверка размера PNG, предел кадра, предел кэша 512 МиБ, проверка свободного места и автоматическое уменьшение окна сохранены.
- Для экспорта 4K исходные 4K-кадры не уменьшаются.
- Если любой клип использует большой пользовательский масштаб, рабочее разрешение повышается; при необходимости сохраняется оригинальное разрешение.
- NVDEC window failure по-прежнему приводит к программному повторному извлечению.

## Автоматические проверки

- `node --test tests/*.test.cjs` — **208/208 PASS**.
- Добавлены тесты планирования рабочего разрешения и сохранения аспектного соотношения.
- Добавлен реальный FFmpeg-тест, создающий PNG в уменьшенном размере и проверяющий число файлов и размеры.
- Добавлены проверки порядка фильтров: CFR/select выполняется до scale; в NVDEC-пути `hwdownload` сохраняется перед CPU scale.
- Существующие проверки временных меток, FPS, аудио, BT.709, raw RGBA, NVENC CBR, NVDEC fallback и экспорта остаются зелёными.

## Локальный benchmark рабочего PNG

Одинаковый исходный файл 4K60, первые 48 кадров целевой 30 FPS сетки, программная FFmpeg-среда контейнера:

| Вариант | Размер PNG-пакета | Средний PNG | Время |
|---|---:|---:|---:|
| Полное 3840×2160 | 361,5 МБ | 7,53 МБ | 7,05 с |
| Рабочее 2400×1350 | 190,3 МБ | 3,96 МБ | 4,45 с |

Изменение в этой среде:
- объём выбранных PNG уменьшился на 47,4%;
- время извлечения выбранных PNG уменьшилось на 36,8%.

Сравнение ресайза до 1280×720:
- direct 3840×2160 → 1280×720 против 3840×2160 → 2400×1350 → 1280×720;
- SSIM: 0,9982;
- PSNR: 54,35 дБ.

Эти числа относятся к локальному FFmpeg ресайзу на тестовой машине/контейнере и не являются замером полного экспорта на GTX 1050 или доказательством идентичности Canvas-композиции.

## Не проверено

- Полный экспорт beta 3.6.26 на Windows с GTX 1050.
- Фактическая скорость NVDEC + NVENC на пользовательском компьютере.
- Визуальное качество сложных проектов с масштабом, поворотом, масками и переходами на нескольких видеодорожках.
- Нагрузочные тесты длинных проектов на диске с небольшим свободным местом.

## Ручная проверка

1. Распаковать beta 3.6.26 в отдельную папку.
2. Выполнить `npm.cmd install`.
3. Запустить `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Start-Montazhnaya-NVENC.ps1`.
4. Импортировать тот же файл 4K60 `montazhnaya_20261102_1710.mp4`.
5. Экспортировать MP4 1280×720, 30 FPS, 5 Мбит/с.
6. Проверить в журнале `NVDEC_PROBE_PASS`, `h264_nvenc`, а также запись `[Оконный кэш исходных кадров] Рабочий кадр уменьшен для разрешения экспорта` с render size около 2400×1350.
7. Проверить отсутствие fallback, число кадров 181, 30 FPS, 6,033 с, BT.709 и средний видеобитрейт в пределах 4,75–5,25 Мбит/с.
8. Прислать `beta-3.6.26-nvenc.log` и итоговый MP4 для внешней проверки.

Вернуться к предыдущей версии можно запуском beta 3.6.25 из её отдельной папки. Beta 3.6.26 не изменяет её файлы.
