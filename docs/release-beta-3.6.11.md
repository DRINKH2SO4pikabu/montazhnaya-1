# «Монтажная» beta 3.6.11 — CFR WebM и единый локальный FFmpeg-экспорт

## Цель

Стабилизировать WebM и встроенный MP4 в Electron: убрать зависимость постоянной частоты кадров от realtime-захвата MediaRecorder там, где доступен локальный FFmpeg, использовать единый покадровый конвейер и проверять готовый файл через ffprobe.

## Что изменено

- В Electron экспорт MP4 H.264/AAC и WebM VP8/Opus либо VP9/Opus использует один план кадров `n / FPS`, offline WAV-mix и потоковую передачу готового PNG-кадра в FFmpeg через `image2pipe`.
- WebM-кодировщики выбираются отдельно: `libvpx` (VP8) или `libvpx-vp9` (VP9); звук — `libopus`, 48 кГц, стерео. Для VP9 включён row-mt. MP4 остаётся H.264/AAC.
- Экспортёр получает список возможностей FFmpeg по узкому preload IPC. В диалоге формата показываются только локальные варианты, чьи требуемые кодировщики и muxer обнаружены. Встроенный realtime MP4 не дублирует локальный MP4, если последний доступен.
- Если в Electron нужный локальный кодек недоступен, браузерный MediaRecorder fallback показывается только как realtime-вариант с явной пометкой, что FPS не гарантирован. Вне Electron браузерные варианты также помечены как realtime.
- Запуск локального WebM/MP4 не требует `MediaRecorder`; используются одинаковые операции подготовки исходных кадров, canvas-композиции, PNG snapshot, бинарного IPC, backpressure, прогресса, отмены и очистки временной сессии.
- Save Dialog подставляет расширение `.webm` или `.mp4` в соответствии с выбранным контейнером.
- Постпроверка WebM проверяет контейнер, выбранный видеокодек, `yuv420p`, точное число кадров, средний FPS, длительность, каждую временную метку кадра и необязательную аудиодорожку Opus.
- Для WebM учитывается точность временной шкалы Matroska/WebM (обычно 1 мс). При 50/60 FPS интервалы PTS могут чередоваться на один квант шкалы; проверка использует допуск на основе фактического `time_base`, но всё равно отклоняет повторные/немонотонные PTS и большие разрывы.
- Opus pre-skip может давать начало аудиопотока около −7 мс. Если ffprobe не выдаёт stream duration, покрытие аудио проверяется по первому PTS и конечному времени последнего аудиопакета, а не ошибочно помечается как отсутствующее.
- Панель «Справка → Диагностика FFmpeg и ffprobe…» теперь отдельно проверяет VP8, VP9, Opus и WebM muxer, выполняет короткие smoke encode WebM VP8+Opus и VP9+Opus и проверяет оба результата ffprobe. В отчёте показываются статусы этих проверок.
- Сводка диагностики перечисляет только форматы, успешно прошедшие пробное кодирование и проверку ffprobe.
- Справка экспорта, обучающий тур и предупреждения для проектов длиннее 10 минут приведены в соответствие с реальными маршрутами: локальные MP4/WebM кодируются offline через FFmpeg, а только browser fallback остаётся realtime без гарантии FPS.

## Форматы и поведение

| Вариант | Кодеки | Конвейер в Electron | FPS |
|---|---|---|---|
| MP4 | H.264 + AAC | PNG image2pipe → FFmpeg | CFR по целочисленному плану |
| WebM VP8 | VP8 + Opus | PNG image2pipe → FFmpeg | CFR по целочисленному плану; PTS с точностью time_base контейнера |
| WebM VP9 | VP9 + Opus | PNG image2pipe → FFmpeg | CFR по целочисленному плану; PTS с точностью time_base контейнера |
| Браузерный fallback | зависит от Chromium | MediaRecorder realtime | Постоянный FPS не гарантируется |

Постоянная частота кадров означает, что кадры рендерятся и кодируются по согласованному целочисленному плану. Это не является обещанием, что разные контейнеры имеют идентичную точность временных меток: WebM использует собственную временную шкалу, поэтому возможна миллисекундная квантизация.

## Проверки

- Unit: поддерживаемые и недопустимые сочетания контейнеров/кодеков, параметры CFR, формат расширения и проверки форматов.
- Реальный FFmpeg: WebM VP8 + Opus при 25 FPS и WebM VP9 + Opus при 60 FPS; ffprobe подтверждает контейнер, видеокодек, `yuv420p`, число кадров, `avg_frame_rate`, аудиокодек и временной диапазон Opus-пакетов.
- Реальный FFmpeg/ffprobe smoke diagnostics: MP4 без аудио, MP4 с AAC, WebM VP8+Opus и WebM VP9+Opus.
- Timestamp check на полном списке кадров, с допуском от time_base контейнера; проверяются монотонность, число временных меток и отсутствие больших пропусков.
- Отмена WebM/MP4 использует тот же управляемый бинарный процесс; текстовая команда `q` не передаётся в PNG stdin.
- Полный автоматический набор: **119/119 тестов, 0 ошибок, 0 пропусков** в рабочем окружении.

## Ограничения и ручная приёмка

- Фактическая производительность VP8/VP9 зависит от CPU, версии FFmpeg и доступных кодировщиков. VP9 обычно тяжелее VP8; для ускорения можно использовать VP8 либо снизить разрешение/FPS.
- Время кодирования не обязано быть realtime; CFR гарантирует расписание кадров, а не скорость кодирования.
- Если локальный FFmpeg/кодек недоступен, realtime fallback прямо предупреждает, что FPS не гарантирован.
- Windows PowerShell/Electron GUI и экспорт реального длинного многослойного проекта на пользовательском компьютере должны быть проверены вручную. Рабочие интеграционные проверки используют локальный FFmpeg/ffprobe в тестовой среде.
- Полная ручная сверка предпросмотра с экспортом для всех 20 переходов, титров, масок, трансформаций и цветовых эффектов остаётся отдельной задачей.

## Затронутые области

- `electron/frame-sequence.cjs` — параметры MP4/WebM и аргументы FFmpeg.
- `electron/main.cjs` — capability IPC, Save Dialog, выбор кодировщика и проверка выходного WebM.
- `electron/preload.cjs` — узкий API возможностей FFmpeg.
- `electron/media-timing.cjs` — допуск временных меток с учётом шага time_base.
- `electron/tool-diagnostics.cjs` — smoke-кодирование WebM VP8/VP9 + Opus.
- `src/renderer/index.html` — выбор формата, маршрутизация FFmpeg/realtime, предупреждения, диагностика и справка.
