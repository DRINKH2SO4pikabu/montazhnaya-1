# Контрольный benchmark — beta 3.6.24

## Цель

Проверить влияние укрупнения окон исходных кадров на экспорт 4K60 → 720p30. Этот тест отделяет корректность NVDEC/NVENC от общей производительности конвейера.

## Подготовка

1. Установить beta 3.6.24 в отдельную папку.
2. Убедиться, что совместимый FFmpeg 8.0.1 установлен в `%LOCALAPPDATA%\Montazhnaya\ffmpeg-8.0.1-nvenc-api13.0`.
3. Установить npm-зависимости один раз:

```powershell
npm.cmd install
```

4. Запустить редактор с правильной сборкой FFmpeg:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\tools\Start-Montazhnaya-NVENC.ps1
```

## Эталонный исходник

`montazhnaya_20261102_1710.mp4`

- H.264 High
- 3840×2160
- 60 FPS
- 362 кадра
- 6,033333 с
- AAC, 48 кГц, stereo

## Настройки экспорта

- MP4 H.264 + AAC
- 1280×720
- 30 FPS
- средний целевой битрейт 5 Мбит/с
- диапазон 0,000–6,033 с

Не использовать предыдущий экспорт 720p как исходник.

## Что должно появиться в журнале

- `NVDEC_PROBE_PASS`
- `videoEncoder: "h264_nvenc"`
- `[Оконный кэш исходных кадров] План окна` с `windowFrames: 48` для начала 4K-источника, если не сработали ограничения кэша/диска
- `[Оконный кэш исходных кадров] Декодировано` с более крупными пакетами
- отсутствие `NVDEC_WINDOW_FALLBACK` и `NVDEC_SOFTWARE_FALLBACK` при штатном прогоне

Если в журнале появляются сообщения об уменьшении окна из-за фактического размера PNG или нехватки места на временном диске, это безопасное поведение, а не ошибка.

## Критерии корректности

- 181 видеокадр, 30 FPS, 6,033 с
- AAC 48 кГц, stereo, синхронный звук
- средний видеобитрейт в пределах 4,75–5,25 Мбит/с
- BT.709 limited
- полный decode test без ошибок
- отсутствие потери/дублирования/перестановки кадров

## Сравнение производительности

Сравнивать только одинаковые исходник, настройки и оборудование. Провести минимум два повтора и записать:

- полное время экспорта;
- чтение/декодирование исходных кадров;
- подготовку кадров;
- передачу кадров FFmpeg;
- длительность FFmpeg-процесса;
- размер окна, фактические байты PNG и число запусков FFmpeg.

Не объявлять ускорение по одному прогону или по сравнению разных исходников.
