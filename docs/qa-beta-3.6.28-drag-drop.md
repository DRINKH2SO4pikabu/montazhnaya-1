# QA — beta 3.6.28: исправление перетаскивания видео из медиатеки

## Наблюдаемая проблема

При перетаскивании видео из медиатеки на таймлайн браузер мог начинать нативное перетаскивание вложенной JPEG-миниатюры, а не родительской карточки видео. Обработчик drop сначала проверял `DataTransfer.files`; такой payload мог попасть в ветку импорта внешних файлов, из-за чего на таймлайне появлялась картинка JPG, а исходное видео оставалось только в медиатеке.

## Исправление

- Вложенное изображение миниатюры явно помечается `draggable=false`.
- Для `.mi-thumb img` отключены pointer events и нативное перетаскивание браузера; сама карточка `.media-item` остаётся draggable.
- При начале перетаскивания карточка передаёт ID через `application/x-montazhnaya-media`; `text/plain` оставлен как совместимый fallback.
- `getDragMediaId()` предпочитает специальный MIME.
- Dragover и drop сначала распознают уже импортированный объект медиатеки, и только затем обрабатывают внешние `DataTransfer.files`.
- Перетаскивание файлов из Проводника на таймлайн по-прежнему направляется через `importAndPlaceFilesOnTrack()`.

## Что ещё требуется подтвердить вручную

Фактический GUI drag-and-drop в Windows Electron не может быть воспроизведён этой тестовой средой. После установки beta 3.6.28 на Windows нужно проверить два сценария:

1. Перетащить видео за миниатюру и отдельно за текст карточки: на видеодорожке должен появиться видеоклип, без отдельной JPG-карточки.
2. Перетащить отдельный JPG или MP4 из Проводника на дорожку: внешний импорт должен работать как раньше.

Также следует проверить двойной щелчок по карточке и drag/drop аудио и обычных изображений.

## Packaging hotfix — PowerShell 5.1

- В исходном ZIP файл `tools/Start-Montazhnaya-NVENC.ps1` содержал два подряд UTF-8 BOM перед `param()`, из-за чего Windows PowerShell 5.1 выдавал `ExpectedExpression` ещё до запуска Electron.
- Удалён лишний BOM; файл сохранён в UTF-8 с одним BOM для совместимости с Windows PowerShell 5.1.
- Добавлен тест `powershell-launcher-encoding.test.cjs`: проверяет один BOM и то, что `param()` начинается сразу после него.
- Повторный `node --test tests/*.test.cjs`: 218/218 PASS.
- Синтаксис всех `.cjs` проверен отдельно. Сам Windows PowerShell 5.1 в среде сборки недоступен, поэтому фактический повторный запуск лаунчера на Windows ещё требуется подтвердить.
