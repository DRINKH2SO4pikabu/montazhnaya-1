# QA beta 3.6.23 — NVENC CBR и повторяемый hardware benchmark

Дата сборки: 2026-11-02
Версия пакета: `3.6.23`

## Изменения

- Профиль `h264_nvenc` переведён с VBR на CBR.
- `-b:v` и `-maxrate` получают одно и то же значение целевого битрейта.
- Для NVENC включены `-strict_gop 1` и `-cbr_padding 1`.
- Профили AMF (`vbr_peak`), QSV и `libx264` не изменялись.
- Скрипт `tools/Test-Montazhnaya-NVENC-API13.0.ps1` проверяет наличие `h264_nvenc`, `cbr_padding` и `strict_gop`, затем выполняет реальное 1-секундное CBR-кодирование. Если проверка CBR не проходит, скрипт прекращает запуск приложения, чтобы не выдавать CPU fallback за GPU benchmark.
- Исправлены тестовые ожидания для NVENC CBR и добавлены точные проверки равенства target/maxrate, размера VBV и CBR-флагов.

## Автоматические проверки

В локальной среде проекта:

- `npm test`: **199/199 PASS**.
- Проверка синтаксиса CommonJS (`node --check` по `electron/*.cjs` и `tests/*.cjs`): ожидается PASS; конкретный запуск фиксируется в релизном протоколе после повторной проверки.
- Реальный NVENC CBR на физической GTX 1050: **ожидает пользовательского запуска**.
- NVDEC + NVENC одновременно на GTX 1050 уже были подтверждены в beta 3.6.22 с FFmpeg 8.0.1, но тот экспорт использовал в качестве источника прежний файл 1280×720, а не оригинал 4K60.

## Известные аппаратные факты

Из пользовательского лога beta 3.6.22:

- драйвер NVIDIA предоставляет NVENC API 13.0; прежняя сборка FFmpeg с требованием API 13.1 была несовместима;
- отдельная сборка Gyan FFmpeg 8.0.1 прошла реальный NVENC smoke-test на GTX 1050;
- для исходного 4K60 файла `montazhnaya_20261102_1710.mp4` проходил `NVDEC_PROBE_PASS`, и окна исходных кадров декодировались командами с `-hwaccel cuda`;
- для финального экспорта на NVENC необходимо повторить тест именно на исходном 4K60 файле.

## Ограничения

- Локальная среда разработки не имеет доступа к физической GTX 1050 и не может подтвердить качество/битрейт NVENC CBR непосредственно на ней.
- CBR делает поток более предсказуемым, но не заменяет проверку реального MP4 через `ffprobe` и полного декодирования.
- Нельзя сравнивать время экспорта разных исходников. В частности, 42,4 секунды в beta 3.6.22 были получены с входом `montazhnaya_20261102_1953.mp4` (1280×720); прежние 151,3 секунды — с оригиналом 4K60 `montazhnaya_20261102_1710.mp4`.
