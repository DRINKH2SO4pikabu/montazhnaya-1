# QA — «Монтажная» beta 3.6.20

## Автоматические проверки

- Валидатор разрешает raw RGBA только для потокового MP4 и кадра не более 32 МиБ.
- Проверяется точный размер RGBA payload относительно ширины/высоты.
- FFmpeg получает rawvideo RGBA по binary stdin без image2pipe/PNG-декодирования.
- Проверяется реальное кодирование raw RGBA в MP4 с точным CFR, числом кадров и BT.709 tags.
- Проверяется полный кадр 3840×2160 RGBA (31,64 МиБ) на входе FFmpeg.
- Проверяется raw RGBA MP4 вместе с AAC и совпадением длительности.
- Проверяются целевой средний битрейт и VBV-профиль.
- Проверяется, что WebM и fallback сохраняют PNG image2pipe.
- Проверяются runtime NVENC smoke-probe и CPU libx264 fallback на уровне реализации.
- Проверяются индекс кадров, backpressure, отмена, WAV, кадровая сетка и синхронизация.
- Проверяется согласованность пользовательской версии `3.6.20` в package/package-lock/интерфейсе.

## NVENC: ограничение среды

В среде разработки FFmpeg перечисляет `h264_nvenc`, но runtime smoke-test завершается ошибкой `Cannot load libcuda.so.1`: здесь нет загруженного NVIDIA CUDA-драйвера/устройства. Поэтому фактический NVENC encode в этой среде не подтверждён. Код автоматически использует `libx264`, если пробное кодирование NVENC на целевом ПК не прошло. Поддержку NVENC необходимо подтвердить на Windows-машине пользователя.

## Не проверено

- Реальный запуск Electron beta 3.6.20 в Windows 10 пользователя.
- Передача полного 31,64 МиБ кадра через реальный `ipcRenderer.invoke` в установленном Windows/Electron на целевой машине. Автоматическая интеграция проверяет полный размер кадра на rawvideo/FFmpeg уровне, а валидатор отдельно проверяет границы буфера.
- Реальный NVENC encode на GTX 1050 пользователя.
- Скорость 4K60 экспорта на пользовательском CPU/GPU до/после. Нельзя считать ускорение подтверждённым только на основании архитектуры и тестов.
- Экспорт длинного многодорожечного проекта и длительный стресс-тест RAM/VRAM.

## Ручная приёмка на Windows

1. Установить патч поверх beta 3.6.19.
2. Выполнить `npm.cmd test` и убедиться, что локальный результат совпадает с 180/180.
3. Запустить `npm.cmd start`.
4. Открыть тот же исходный Grok MP4, который использовался для предыдущего 4K60 теста.
5. Экспортировать тот же фрагмент: MP4 H.264 + AAC, 3840×2160, 60 FPS, целевой средний битрейт 20 Мбит/с.
6. В сводке экспорта проверить строку `кадры RGBA rawvideo` и выбранный H.264-кодировщик: `h264_nvenc` при успешном runtime test либо `libx264` при fallback.
7. Передать итоговый MP4 и текст/скриншот сводки. Проверить фактический битрейт, 362/363 кадра в зависимости от точной границы выбранного участка, 60 FPS, звук AAC, BT.709 и время каждого этапа.

## Критерий успешной ручной проверки

- Экспорт завершён без ошибок.
- Разрешение, FPS, число кадров, длительность и звук совпадают с планом.
- Все четыре цветовых атрибута BT.709 правильные.
- Средний видеобитрейт близок к выбранной цели (с учётом допустимого разброса rate control).
- В отчёте подтверждён транспорт RGBA rawvideo; если транспорт PNG, нужно выяснить причину fallback (WebM или кадр больше 32 МиБ).
- Время подготовки кадра/общего экспорта сравнивается с beta 3.6.19 на том же исходнике и тех же настройках. Только этот тест подтвердит реальное ускорение.
