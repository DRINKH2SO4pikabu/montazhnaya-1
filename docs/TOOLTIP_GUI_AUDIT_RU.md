# Визуальный GUI-аудит подсказок Montazhnaya

## Запуск

Требуется Windows 10/11 x64, Node.js 22.12.0 или новее, npm и доступ к GitHub и npm registry.

Открой обычный PowerShell (права администратора не нужны) и выполни:

```powershell
$script = Join-Path $env:TEMP "Test-Montazhnaya-Tooltips.ps1"
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/DRINKH2SO4pikabu/montazhnaya-1/main/tools/Test-Montazhnaya-Tooltips.ps1" -OutFile $script
powershell.exe -NoProfile -ExecutionPolicy Bypass -File $script
```

Скрипт загружает исходный код ветки `main` во временную папку, синхронизирует зависимости, получает Electron runtime и запускает исходный проект напрямую. Установщик Setup и Portable EXE не используются; в Windows не устанавливаются системные компоненты. После завершения временная копия удаляется, если не передан параметр `-KeepWorkingCopy`.

Окно редактора будет видно во время проверки. Для локального подключения к нему используется Chromium DevTools Protocol на loopback-порту (по умолчанию 9337). Порт не предназначен для доступа из сети.

## Объём проверки

- Все 36 выбираемых языковых вариантов.
- Все 364 строки отдельного каталога подробных подсказок.
- Все определения подсказок для действий и элементов управления из `UI_HELP_ACTIONS` и `UI_HELP_IDS`.
- Переопределения для начинающих из `BEGINNER_ACTION_HELP` и `BEGINNER_ID_HELP`.
- Реальные функции `showFunctionHelp()` и `buildFunctionHelpContent()` внутри работающего Electron renderer.
- Все 364 подробные строки по очереди помещаются в настоящую карточку подсказки; проверяются четыре визуальные роли: заголовок, основной текст, инструкция и совет.
- Все определения действий и полей/контролов проверяются отдельно, включая beginner-friendly overrides и реально видимые элементы интерфейса.
- Три размера области отображения (CSS viewport): 1024×700, 1366×768 и 1920×1080. Размер физического окна Windows при этом не изменяется.
- Направление RTL для арабского и иврита, координаты всплывающей карточки и признаки обрезания текста.
- Фактические переведённые значения, оставшиеся русские фрагменты и поля, которые не попали в отрисованную карточку.

Для каждого языка сохраняется скриншот одной из самых длинных карточек подсказки.

## Результаты

## Тестовый доступ к реальному renderer

Весь код подсказок находится внутри замыкания renderer и недоступен напрямую из глобального контекста DevTools. Для аудита добавлен узкий мост window.MontazhnayaTooltipQA: он экспортирует только функции и каталоги, нужные проверке, и создаётся лишь при наличии query-параметра tooltip-audit=1.

PowerShell-лаунчер временно задаёт переменную процесса MONTAZHNAYA_TOOLTIP_QA=1; Electron преобразует её в локальный query-параметр страницы. При обычном запуске редактора переменная не устанавливается и QA-мост не создаётся. Параметр разрешён навигационным фильтром только для того же локального index.html.

qa/tooltip-gui-audit.cjs обращается к внутренним функциям исключительно через этот мост. Это устраняет ошибку готовности, вызванную попыткой найти функции внутри замыкания как глобальные переменные.


По умолчанию папка результатов создаётся на рабочем столе:

`Montazhnaya-Tooltip-Audit-YYYYMMDD-HHMMSS`

В ней будут:

- `tooltip-gui-audit-summary.md` — сводка по всем языкам.
- `tooltip-gui-audit.json` — полный машинно-читаемый отчёт.
- `tooltip-gui-audit-details.csv` — строки по каждой проверенной карточке, каждому из 364 фрагментов и размеру области отображения.
- `tooltip-<locale>.png` — 36 скриншотов.
- ZIP-архив со всеми перечисленными результатами.

Для другой папки можно запустить скрипт с параметром `-OutputDirectory "D:\\MontazhnayaAudit"`.

## Ограничения

Это технический GUI smoke test. Каждая из 364 подробных строк каждого языка фактически вставляется в карточку и проверяется на вывод, потерю текста и переполнение; отдельно проверяются карточки действий/элементов управления и их положение. Тест не оценивает художественную естественность перевода. 34 дополнительных языка остаются машинно-ассистированными черновиками и требуют вычитки носителями. Подсказки, зависящие от конкретного открытого клипа, импортированного файла или состояния проекта, требуют дополнительной проверки с отдельным тестовым проектом и медиафайлами.
