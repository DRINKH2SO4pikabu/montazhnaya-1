# Localization architecture — beta 3.6.45

## Current scope

The localization runtime is local/offline and supports system-language detection, persistent manual preference, live switching without restarting, BCP-47 region and script subtags, placeholder-aware messages and dynamic DOM updates. Russian remains the source language. English is the reference pack with 436 dictionary entries.

The application offers 34 preview locales in addition to Russian and English: 24 international language packs and 10 regional language/script variants.

## Coverage

All 24 international packs map the full 436-key reference dictionary with zero English fallback entries. Nine regional base-language packs — Kazakh (`kk`), Uzbek Latin (`uz`), Azerbaijani (`az`), Georgian (`ka`), Armenian (`hy`), Turkmen (`tk`), Kyrgyz (`ky`), Tajik (`tg`) and Belarusian (`be`) — also map all 436 keys with zero English fallback.

Uzbek Cyrillic (`uz-Cyrl`) is available separately and maps all 436 keys. It is generated by deterministic transliteration from the Uzbek Latin draft, not an independent Cyrillic translation; metadata identifies it as `transliteration-draft` pending native-speaker review.

Regional locale metadata tracks `localeMappedCount`, `englishFallbackCount`, `englishFallbackKeys`, `translationStage`, `translationQuality` and `completedTranslationWave`. All regional packs remain `preview` until review and UI QA are complete.

## Runtime behavior

- First launch detects `navigator.languages` / `navigator.language` and chooses the closest supported locale. Region and script subtags are considered, so `uz-Cyrl-UZ` resolves to Uzbek Cyrillic while `uz-UZ` resolves to Uzbek Latin.
- The user can switch language from Help → Interface language without restarting. The preference is saved locally under `montazhnaya_locale_preference_v1`; project and media files are not modified.
- The renderer loads the English reference pack before any non-Russian locale. Lookup order is selected locale → English → original Russian source string.
- Each complete locale pack maps all 436 source keys. Mapping counts are source-key mappings; duplicate source labels can still map through shared labels, and key coverage does not represent linguistic review.
- Media filenames, clip names, project titles and user-authored text are not translated automatically.

## Beginner tour catalog (Stage 7)

The seven-step beginner tour uses permanent semantic IDs instead of Russian or English phrases embedded in the renderer. Its 21 fields (title, body and tip for each step) are registered by `src/renderer/locales/beginner-tour.js` after the core semantic catalogue and before notification and IPC catalogues. The catalogue provides 21 translations for each of the 36 selectable locales (756 strings total; 714 are additions across the 34 preview locales).

The tour renderer resolves each field through `MontazhnayaI18n.t()` and redraws an open tour after the `montazhnaya:locale-changed` event. The automated audit checks that no locale is empty or silently uses the English reference for these keys, and that instructions use the same translated labels as the corresponding Import Media, Split, Transitions and Export controls. The detailed tutorial copy for the 34 preview locales is machine-assisted draft text; fluent native-speaker review remains required.

## Scripts and fonts

Arabic (`ar`) and Hebrew (`he`) declare `direction: "rtl"`. Uzbek Latin and Cyrillic are separate variants. Georgian, Armenian and Cyrillic locale packs declare script-aware font fallbacks. These CSS/font declarations do not prove that every target Windows installation has the same fonts or shaping behavior.

## Editorial terminology pass (Stage 8)

`src/renderer/locales/editorial-overrides.js` provides a small, explicit before/after correction layer for high-frequency video-editing concepts. It is registered before `i18n.js`; the selected locale pack is patched after it is dynamically loaded, before the pack is used for translation. The layer clones the frozen message map, preserves the source pack, adds `editorialRevision` and `editorialReviewStatus` metadata, and is idempotent.

Stage 8 applies targeted terminology corrections to all 34 preview locales, including clear false-friend fixes for image resolution, more explicit wording for ripple delete, text overlays and snapping, plus selected track/audio/timeline labels. The before/after matrix and rationale are maintained in `qa/editorial-terminology-stage8.csv`.

This is a machine-assisted editorial pass over a high-frequency terminology subset; it does **not** certify the full 436-key translation set in any locale. All preview languages remain subject to fluent native-speaker review. Uzbek Cyrillic now has independent corrected terminology for the affected keys, but the rest of that pack remains a transliteration draft.


## Stage 9 full-dictionary audit and editorial layer

The immutable source corpus is captured in `source-messages.js` before English guide strings are appended. QA must use `MontazhnayaLocaleSourceMessages` as the 436-key base set; `packs.en.messages` may later contain additional guide phrases and must not be mistaken for the base corpus. Stage 9 uses `editorial-overrides.js` to apply locale-specific corrections at runtime without mutating the Russian/English source packs. `qa/audit-full-dictionary-editorial-stage9.cjs` enumerates 436 × 34 = 14,824 translation cells, validates placeholders and generates the matrix and review flags. This pass is machine-assisted and does not replace native-speaker review.
